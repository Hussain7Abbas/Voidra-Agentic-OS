# P12 automated verification report

Date: 2026-09-20  
Host: Apple M4, 24 GB RAM, Apple Silicon (`arm64`), macOS 26.5.2  
Scope: release composition, backup/restore, transactional schema migration, production fixture lockout, traceability, and operator documentation

## Outcome

The P12 automated release-candidate scope is implemented. Voidra can export and fully verify a workspace snapshot, restore it into a clean root/profile with stable identity and durable state, retain unavailable shared references for later location, omit rebuildable indexes and credentials, and reject corrupted/newer-schema/low-space recovery paths. The Apple Silicon directory package now emits a digest manifest and runs without a development server.

P12 is not a complete public-release sign-off. Signing/notarization, clean-account installation/update, physical permissions and automation, real audio/language measurements, actual sleep/wake, and phone/TLS/LAN acceptance remain unchecked. Q01/Q02/Q03/Q07/Q10/Q11/Q13 retain their recorded provisional defaults unless the user answers them.

## Recovery evidence

- Export uses a hidden stage and atomic final rename, hashes copied payload bytes, records modes and sizes, and preflights destination space.
- Restore parses a strict versioned manifest, verifies all bytes before destination creation, requires a new root, stages the copy, and rejects newer database schemas.
- Canonical Markdown, persona/rules, history, plans/schedules, agent journals, voice/handoff state, and artifacts are ordinary durable files in the snapshot.
- SQLite note indexes, transient rename journals, temporary files, and symbolic links are explicitly omitted. The E2E opens Notes after restore and rebuilds the index from canonical Markdown.
- Secure credentials and opaque credential references are not exported. Provider names only are presented as a reauthorization checklist.
- Shared bases are represented once by identity/path/grant. The clean-profile journey removes the source before restore and verifies that the attachment remains present but unavailable.
- An existing supported application database passes `quick_check` before Voidra creates a mode-`0600` SQLite snapshot that includes committed WAL content. The full multi-version upgrade chain is one transaction; a simulated interruption in the later step leaves the original `user_version`, tables, and data unchanged while retaining the readable pre-migration snapshot.

## Release evidence

- `release/release-manifest.json` records the package tree digest, lockfile digest, version/schema data, arm64 executable inspection, total files/bytes, and the unsigned/notarized boundary.
- Next.js receives a version-derived deterministic build ID. With the same source and pinned `SOURCE_DATE_EPOCH`, two consecutive complete package builds produced the identical tree digest. Dependencies are locked by `pnpm-lock.yaml`; `make install-frozen` enforces the lock.
- The packaged smoke starts `Voidra.app` from `release/mac-arm64` with its embedded renderer/service and confirms no E2E diagnostic bridge is exposed.
- The service child receives an explicit runtime mode from Electron. A production process ignores inherited legacy E2E/remote fixture flags and still requires TLS material for remote hosting.

## Performance evidence

The P02/P03 reports contain single-run 10,000-note startup/index/search/editor/graph and aggregate-memory observations on this host. Agent, voice, native, and remote fixtures cover bounded cancellation/concurrency behavior, but no percentile speech latency, idle energy, physical UI automation latency, or combined long-session workload has been measured. Those are release acceptance items, not silently inferred from unit coverage.
