## Required scenario evidence

- Work-private and Personal-private sentinels remain absent from the other workspace's accessible search. Shared read-only/writable, detached, unavailable, and revoked-during-retrieval states are covered with real files.
- Work creates a note through its writable attachment; Personal sees the same file through its read-only attachment and cannot save or create there.
- Two stale shared writers serialize; one saves and the other receives a conflict. Separate manager instances prove the physical lock returns a retryable busy result, and a dead-owner lock recovers.
- Graph tests cover duplicate titles, exact source labels, explicit cross-base links, same-base links, deterministic local depth, tag highlighting, and filter-only mode.
- Memory tests cover confirmed versus inferred provenance, expiry, editing, deletion, context selection, malformed metadata, restart persistence, and Work/Personal separation.
- Moving an attached folder makes it visibly unavailable. Locate updates the original base identity and restores search without copying source content.

## Honest boundaries

- Shared parsing currently scans canonical files per operation rather than maintaining a persistent application-owned shared index. It reflects external edits immediately but makes repeated large-base search more expensive.
- The SVG overview is bounded and deterministic, not a production force-layout/WebGL visualization. The accessible list and service graph semantics are the acceptance boundary; richer layout remains an optimization.
- Read-only is the provisional Q08 default, not a recorded answer. There is no remote multi-device collaboration protocol; the lock coordinates local processes sharing the same physical directory.
- Detach prevents future retrieval. It cannot retract text already displayed, copied, saved to conversation history, or sent to a provider.
- Semantic/vector similarity is not implemented and is not represented as an explicit graph edge.
