# P02 verification report

Date: 2026-09-20  
Host: Apple M4, 24 GB RAM, Apple Silicon (`arm64`), macOS 26.5.2  
Scope: Markdown editing, local indexing, links, history, conflict and rename recovery

## Outcome

P02 is complete under the documented provisional defaults. Users can create and edit canonical Markdown, use source/split/preview modes, navigate resolved links and backlinks, search text/tags, rename with exact reference updates, resolve external-write conflicts, restore revisions, and rebuild a deleted index. Workspace-owned source and recovery files survive application restart.

## Required scenario evidence

- Parser fixtures cover aliases, anchors, ordinary links, escaped/code syntax, malformed/remote links, nested and frontmatter tags, wrapped paths, and Unicode.
- Real temporary files prove revision comparison, atomic replacement failure, two successive external races, all conflict resolution branches, restore, and retention of 100 normal revisions plus conflict snapshots.
- Duplicate titles stay ambiguous; a path-specific link resolves. In-app rename changes only indexed target spans, keeps prose unchanged, and an interrupted journal resumes without duplicate substitutions.
- Traversal, absolute/non-Markdown paths, and symlink escapes are rejected.
- Real SQLite tests cover deletion, reappearance, external move, broken links, tag-only search, index deletion/rebuild, and debounced watcher convergence.
- Electron tests exercise sanitized preview, wiki navigation, backlink navigation after rename, persisted file bytes, external conflict UI, revision restore across restart, and index recreation.

## Provisional 10,000-note measurement

The scale fixture created 10,000 real Markdown files in 100 directories, each with a tag and wiki link, then launched the production-built Electron application with a persisted workspace registration. One local run measured:

| --- | ---: |
| Launch, full index, and usable bounded explorer | 8,424 ms |
| Indexed search returning one note | 74 ms |
| Open selected note into CodeMirror | 70 ms |
| Eight-character editor input to visible dirty state | 43 ms |

The working set summed Electron Browser, GPU, Utility, and Tab metrics for this synthetic run. These values include automation overhead and are neither percentile data nor committed budgets. Q07 remains unanswered, so the result supports the provisional 10,000-note target only on the recorded host. The explorer renders the first 250 summaries and directs users to search rather than mounting 10,000 buttons.

## Honest boundaries

- Source/split preview and built-in revisions follow provisional Q06/Q09 defaults; live-preview selection/composition behavior and Git history were not implemented.
- The scale run is a single synthetic local measurement. It does not establish Intel, network-volume, 100,000-note, or long-session memory behavior.
- External moves preserve bytes but currently create a new document identity; in-app journaled renames preserve identity and references.
- Filesystem watchers can fail or miss events at the operating-system boundary. Status/error UI and explicit rebuild provide recovery; automated coverage does not simulate a kernel overflow notification.
- Markdown preview is sanitized and non-executable. HTML artifact execution remains isolated P08 work.
