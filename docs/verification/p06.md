## Required P06 scenario evidence

- The catalog fixture verifies official Registry normalization, exact package versions, review labels, supported launch proposals, requirements, cached offline results, malformed/minimal declarations, and continued custom setup availability.
- A disposable MCP SDK v2 stdio server runs as a real child process without a shell. It verifies arguments, a workspace-only working directory, minimized environment, tools, a resource, a prompt, known tool errors, process crash, timeout, stop, disable, remove, and restart state recovery.
- A raw local Streamable HTTP fixture verifies bearer authorization, missing/revoked credentials, reconnection to the same connection identity, paginated tools, capability definition changes, protocol errors, and an invalid-response startup failure.
- Tool calls are prepared separately from approval. A changed capability invalidates stale review. Timeouts and process loss after a call starts become uncertain instead of being replayed.
- The automatic OpenRouter-shaped fixture receives only ready MCP tools, pauses on an exact reviewed connection/tool/argument scope, observes the result, and treats transport loss during a started call as an uncertain interruption.
- Work and Personal hold physically separate MCP registries. Personal cannot list Work's server, and a manipulated request using Work's connection ID fails with `WORKSPACE_CONFLICT`.
- A failed update retains the prior configuration for explicit rollback. Reconnection succeeds without changing the connection ID or secure credential binding.
- Real-Electron credential coverage stores a bearer token through the narrow preload API, proves plaintext is absent from workspace metadata and encrypted credential bytes, crashes the local service, restores the credential in memory, and reconnects.

## External-system boundary

Default tests make no request to the public MCP Registry and authorize no real third-party account. Registry behavior is exercised through a local HTTP fixture matching the documented API shape. Both MCP transports are real protocol connections: stdio uses a disposable child built with the official server package, and Streamable HTTP uses a local JSON-RPC server.

Q04 is still unanswered, so a designated calendar/email/task provider and test account do not exist. The exit criterion's real connector smoke is therefore explicitly deferred; this report does not claim live OAuth, provider revocation semantics, public Registry availability, or compatibility of an arbitrary catalog entry.

## Honest boundaries

- P06 supports direct stdio and Streamable HTTP plus bearer authorization. It does not implement OAuth discovery/browser redirects, arbitrary secret headers, secret local environment variables, legacy SSE, sampling, elicitation, or roots negotiation.
- Selecting declared setup fills an exact pinned proposal and requirements for review. It does not perform a hidden package installation; the configured executable runs only when the user explicitly connects.
- A configured local executable runs with the current macOS user's authority. Workspace cwd and Voidra grants do not provide an OS sandbox.
- Capability and action history currently use an atomic workspace JSON registry. It is bounded by normal use but does not yet implement retention compaction for high-volume MCP activity.
- The packaged artifact is unsigned because no valid Developer ID identity is installed. Package smoke is launch evidence, not notarization or distribution evidence.
