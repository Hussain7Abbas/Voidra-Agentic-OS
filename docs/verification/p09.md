# P09 automated verification report

Date: 2026-09-20  
Host: Apple M4, 24 GB RAM, Apple Silicon (`arm64`), macOS 26.5.2  
Scope: scoped file actions, recoverability, native capability reporting, target freshness, device lease, takeover, and automatic-task integration

## Outcome

P09 automated implementation is complete for the safe file layer, reviewed OpenRouter tool path, native command protocol, and deterministic desktop adapter. The production build can open an exact reviewed path or named application through Electron. It reports real macOS Accessibility and screen-capture state, but deliberately does not claim production Accessibility/visual control without the future stable signed helper.

The phase is not fully accepted on real systems: Q02/Q03/Q04/Q12 remain unanswered, no signed helper identity exists, and the two representative workflows have not been exercised against physical third-party applications with Accessibility/Screen Recording consent.

## Scenario evidence

- A real selected temporary folder is attached to Work. A move stays pending until exact approval, updates the filesystem and journal, and undo restores the original file.
- Integration tests execute copy, move, create, recoverable trash, and each undo path against real temporary files.
- Traversal, cross-workspace root handles, duplicate destinations, symbolic-link sources, duplicate approval, and paths outside the chosen root fail closed.
- A local OpenRouter-shaped provider receives `file_action` only after a root exists. The move pauses for P05 approval, executes in that root, records an automation action, and returns the observed result before task completion.
- The deterministic adapter reports explicit capability states. Accessibility denial produces a failed action and useful error; the UI never labels it completed.
- An activation with a stale target revision fails before interaction.
- Work holds the device lease while Personal queues. Status exposes the Work owner and queue depth. User takeover interrupts both the active and queued actions; neither is replayed.

## Honest boundaries and pending acceptance

- Native target inspection/activation used the deterministic adapter. No automated result is presented as proof of macOS Accessibility, screen capture, Apple Events, input injection, focus behavior, or app compatibility.
- Production `open-path`/`open-app` is implemented through Electron but was not allowed to launch a personal application during automated tests.
- The signed native helper, hardened caller identity, consent persistence across upgrades, visual fallback, multi-display coordinates, and two representative physical-Mac workflows remain P09 acceptance work.
- The packaged artifact is unsigned because no valid Developer ID identity is installed.
