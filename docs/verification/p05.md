# P05 verification report

Date: 2026-09-20  
Host: Apple M4, 24 GB RAM, Apple Silicon (`arm64`), macOS 26.5.2  
Scope: OpenRouter streaming, durable automatic tasks, workspace context, grants, limits, cancellation, and restart recovery

## Outcome

P05 is complete for the file-tool agent boundary. A workspace can securely configure an OpenRouter credential, choose a model, start and inspect a streaming automatic task, approve and reuse an exact path-scoped grant, revoke it, cancel one or all tasks, and safely resume only provider-side interruptions. The runtime rebuilds current authorized context before every provider step and will not replay a tool whose effect became uncertain across a service crash.

## Required P05 scenario evidence

- An OpenRouter-shaped SSE fixture verifies selected-model requests, streaming text, fragmented tool calls, usage accounting, and serialized tool execution through the production adapter.
- Missing credentials and categorized authentication, unsupported request, rate-limit, offline, malformed stream, and server failures produce bounded, inspectable outcomes. Retryable failures retry at most twice and never after partial output.
- The UI previews exact tool arguments. Approval creates a workspace-owned path grant; unchanged scope can be reused, while expiry or revocation blocks the next effect. Traversal, internal metadata, directories, and symlink escapes fail before an effect.
- Cancellation is verified during a live provider stream and while a tool is awaiting approval. Stop All covers active tasks from multiple loaded workspaces.
- A fixture crash after a write commits but before its result is recorded produces an uncertain interrupted task. Restart does not replay the write. A provider-only interruption can resume safely.
- Switching Work to Personal while Work streams does not expose or reassign the task. Registries and grants remain physically located under their owning workspace.
- Effective persona, target-scoped instructions, active memory, and explicitly selected notes are re-resolved before each step. Detaching a selected shared base mid-task prevents the next provider request.
- Step, token, and wall-clock budgets produce interrupted/limited results rather than success. Model, usage, elapsed runtime, output, errors, context revisions, and recent events remain inspectable.
- Secure-credential E2E runs without an environment key, sets the key through Electron main, verifies that its encrypted file and task journal exclude plaintext, runs a task, and deletes the credential.

## Provider and secret boundary

Default tests use a local HTTP server that implements the relevant OpenRouter Chat Completions SSE shape. The real adapter, child service, IPC path, journal, grants, abort signals, and filesystem effects execute. No request reaches OpenRouter and no paid model is invoked.

The suite did not run an opt-in live OpenRouter smoke because no user credential was supplied for external testing. It therefore demonstrates protocol behavior and error handling, not current availability or behavior of any particular hosted model. The selected model is called directly; P05 deliberately has no silent model fallback.

Electron `safeStorage` is exercised in the real Electron E2E process. The test proves the renderer cannot read the credential through the preload API and that plaintext is absent from the encrypted file and task journal. It does not independently inspect macOS Keychain records.

## Honest boundaries

- P05 tools are local UTF-8 reads and atomic writes. Account/domain-scoped grants begin with MCP/browser capabilities in P06/P08; they are not simulated as file metadata.
- Token usage comes from provider usage events. A monetary budget is not estimated from a changing price catalog; the enforced optional usage budget is tokens.
- The event journal records model output, selected source content in provider messages, and tool results inside the owning workspace. Secret-pattern redaction is defense in depth, not a guarantee that arbitrary source prose contains no sensitive material.
- Uncertain writes require human reconciliation. The current UI refuses resume but does not yet provide a purpose-built reconcile-and-mark-observed workflow.
- Tests use deterministic local files and fixtures. They do not prove arbitrary OpenRouter models support tools or validate live provider routing, pricing, retention, or uptime.
